# CreditLens: Loan Default & Credit Risk Analytics

An end-to-end credit risk analytics project on the public LendingClub loan data. Raw CSV -> documented
cleaning -> PostgreSQL star schema -> SQL risk analysis -> EDA -> default-prediction models ->
approval-policy simulation -> executive summary.

## 1. Project overview
CreditLens simulates a real analytics engagement for a lender. Raw loan records are profiled and cleaned with every
decision documented, loaded into a PostgreSQL star schema, analysed with SQL and Python, and turned into a risk
segmentation, a time-validated default model and a lending-policy simulation. Every number in the reports is generated
by the pipeline from the data; nothing is typed in by hand.

## 2. Business problem
A lender wants to approve good borrowers and avoid loans that go bad. Which borrower and loan characteristics predict
default, how much risk does each segment carry, and what approval policy would reduce defaults without rejecting too
many good customers? See `reports/executive_summary.md` (generated by the pipeline) for the answers.

## 3. Objectives
- Portfolio risk: default rate by grade, term, purpose, income, DTI, FICO, state and issue year.
- Pricing check: is the interest rate charged in line with observed default rates?
- Modelling: logistic regression and gradient boosting, validated on a later time period.
- Signal source: how much predictive power comes from borrower data alone, without the lender's own grade and rate?
- Policy: quantify defaults avoided versus good loans lost at different approval cutoffs.

## 4. Dataset
LendingClub accepted loans 2007-2018Q4, from Kaggle:
https://www.kaggle.com/datasets/wordsforthewise/lending-club (about 2.2 million loans, about 150 columns).
Scope: finished loans (Fully Paid, Charged Off, Default) issued 2012-2015. Target `is_default` = Charged Off or Default.
The raw file is not stored in this repo. See `docs/PROJECT_SCOPE.md` and `docs/DATA_DICTIONARY.md`.

## 5. Method
1. **Cleaning** (`src/data_prep.py`): finished loans only, parsed dates/terms/rates, invalid values set to missing,
   outliers clipped using training-year percentiles, post-origination (leaky) columns never loaded.
   Produces `reports/data_quality.md`.
2. **PostgreSQL** (`sql/`, `src/load_to_postgres.py`): staging table, star schema (`fact_loans` + date, grade, purpose,
   state and borrower-profile dimensions) and a reporting view.
3. **SQL analysis** (`sql/03_analysis_queries.sql`): 18 documented queries using joins, CTEs and window functions
   (RANK, LAG, NTILE, rolling and cumulative sums).
4. **EDA** (`src/eda.py`): segment tables and charts.
5. **Modelling** (`src/model.py`): train on loans issued before 2015, test on 2015. Feature sets `full` and
   `borrower_only`; metrics: ROC-AUC, Gini, KS, PR-AUC, Brier score, decile calibration, permutation importance.
6. **Policy simulation** (`src/policy_simulation.py`): reject the riskiest X% of applicants and measure the trade-off.
7. **Reporting** (`src/make_report.py`): generates `reports/executive_summary.md` from the computed outputs.


## 9. Limitations
- Only accepted loans are observed (no reject inference), so there is selection bias.
- No profit, cost or recovery data: financial impact is gross principal exposure, not net loss.
- Grade, sub-grade and interest rate are lender-assigned; borrower-only models are reported alongside.
- US consumer loans from 2012-2015; findings may not transfer to other periods or markets.
- Associations are not causes; a model score should support, not replace, credit judgement.
